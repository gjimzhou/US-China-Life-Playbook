# 事实复核记录

这里保存逐项来源证据与未覆盖范围。记录日期表示那次实际检查的时间；旧记录中的“待核”“本轮完成”都是当时状态，不能直接当作当前结论。

## 从哪里继续

| 要找的内容 | 入口与读法 |
|---|---|
| 当前到期任务 | [自动维护队列](https://github.com/gjimzhou/US-China-Life-Playbook/issues/7)：到期及七天内待复核事项；不表示正文已经失效 |
| 某个范围的最新进展 | [复核台账](../review-registry.json)：按范围ID找到 `latest_review_record`，读取最近尝试及缺口 |
| 最近一次完整核验 | 同一台账的 `review_record` 与 `last_verified`；最近尝试可能只是部分完成，不能替代完整基线 |
| 来源变化或访问故障 | [官方来源监测](../../docs/maintenance/source-watch.md)：与到期队列分别查看 |
| 怎样记录与提交 | [持续维护工作流](../../docs/maintenance/maintenance-workflow.md)：证据模板、关联检查和发布步骤 |

先读最新尝试，再沿记录中的链接回看基线和之前未解决的问题。`last_verified: null` 表示尚未建立整个登记范围的完整基线，不表示已经发现正文错误。完成状态只覆盖记录明确列出的主张，不是整章或所有地区的认证。

## 新增或续写记录

使用 `YYYY-MM-DD-topic.md` 文件名，说明实际读取的主张、来源位置、适用条件、处理结果与剩余缺口。续核时链接此前记录，保留证据沿革；原记录追加续核也须写明新日期和范围。

有充分证据确认无需修改时，也应记录核对依据。访问失败或部分完成只更新最近尝试；完整覆盖登记范围后，才更新完整基线。具体字段及期限处理以维护流程为准。

本页不手工复制台账的完成数量、最近日期或当前待办，避免出现第二套过期状态。记录文件保留在本目录，最新入口由台账维护。

## 验收与状态

本轮目标是逐页细读后留下结论，修复阻断与主要可执行性缺口，按批验证和上线。**当前仅完成92页结构盘点；下表明确哪些已细读，不能把全表当作92页全文审定。** 细读是编辑者检查适用范围、下一步、交接、异常和证据，不等于全文事实核验或真实用户试办。新增与改动的动态规则另有来源记录。

章节允许承担概念解释、机构目录或风险提醒，模板允许保持空白；不是每页都要加长或套相同表格。实际场景应能找到起手动作、两边联系对象、所需资料、依赖顺序、失败分支与可确认的结果。新增字数、链接数和自动词频不作为质量分数。

## 本轮问题与处理顺序

| 优先级 | 问题与范围 | 验收条件／当前状态 |
|---|---|---|
| P1 | 迁居、远程照护、跨境汇款有两端任务但缺具体接手与结束证据 | 本批三份流程草稿；逐项给出受理方、资料、异常和结束证据，完成CI与上线后登记PR |
| P1 | 身份变更、境外丢证的原件占用和旅行依赖不清 | 核验官方办理路径，补退件／赶不上行程分支；不编造统一补办时长 |
| P1 | 退休、保险变更存在“申请”与“实际生效”的衔接缺口；退休页HSA交叉引用不匹配 | 修正引用，按个人／家属分别补生效确认及未获批安排；资格期限逐条查官方依据 |
| P1 | 高后果主章有大量地区、费用与期限规则，结构盘点不能背书 | 逐页识别具体可疑或缺依据断言，连接已有事实台账；能核实则纠正，不能核实则收窄或撤除断言，不批量刷新日期 |
| P2 | 生育、宠物、同居、殡葬及多事并发仍有首次办理缺口 | 结合逐页细读补具体情境；区分法定程序、机构要求与可选消费 |
| P2 | 覆盖表停留在早期批次、维护文件数量过时 | 本批更新维护入口；后续直接更新本表，不再每轮随机选单页或另建重复待办 |

这些是当前发现与审查方向，不表示未细读的页面已经确定有错误。正式任务状态仍以[当前待办](backlog.md)与GitHub Issues为主要入口；本表是该任务的逐页验收附件，事实期限仍由原事实台账管理。

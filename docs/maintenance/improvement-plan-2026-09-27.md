# 中美双栖人生指南改进方案

[文档导航](../README.md) · [当前维护待办](backlog.md) · [维护工作流](maintenance-workflow.md)

编写日期：2026-09-27。面向项目维护者，涵盖阅读体验、编辑质量、工程检查与建议实施顺序。

**性质与范围：** 本文是改进建议，不是已批准的实施计划、当前缺陷清单或完成记录。依据项目首页、阅读网站与编辑进度提出的建议，需要先与当前实现及维护队列核对。时间安排、分工和验收指标均为建议值，不代表承诺或已测得的结果。实际任务状态以 [GitHub Issues](https://github.com/gjimzhou/US-China-Life-Playbook/issues) 和[当前维护待办](backlog.md)为准。

## 建议方向

让读者更快找到适用于自己的下一步，理解适用条件，并直接进入相应官方来源。下一轮先选择五个常见场景，统一行动页结构，清楚显示事实核验范围，再根据真实试读结果决定是否扩展。

项目已有40章正文、场景清单、检索、收藏、阅读进度与离线下载等基础。[项目首页](../../README.md)说明了这些能力与目标读者。内容丰富之后，改进重点是帮助读者在时间有限时判断“哪一条适用于我”。

[编辑进度](../../references/editorial-status.md)已区分结构检查、来源覆盖与事实核验，并记录剩余缺口。建议把这种区分带到具体行动旁边，展示适用范围、来源支持的内容与核验日期。

下一轮建议交付：

- 五个采用统一结构的场景页，明确适用对象和下一步。
- 围绕常见处境调整的首页入口，以及自然中文搜索测试集。
- 可复用的事实审查记录与内容一致性检查。
- 真实读者试读记录、重要事实审查结果和发布验收记录。

第1至3节说明阅读体验与编辑标准，第4至5节说明跨境流程与工程检查，第6至7节给出实施顺序和验收建议，第8节列出来源与实施前需要确定的事项。

## 1 阅读体验与导航

### 优先按处境进入

阅读首页已有场景路线、100件生活小事、清单、下载、术语与准备顺序、证据筛选等入口。建议优化这些入口的主次，让第一次来的读者先找到起点，再了解全书结构。

首页以“你现在遇到了什么？”引导，下列六类入口作为候选。最终应根据读者反馈选定，而不是把候选列表直接当成需求结论。每个入口直接进入简短行动页，并提供完整章节作为延伸阅读。

| 建议入口 | 读者需要解决的问题 |
| --- | --- |
| 刚到美国 | 找出适用于自己的初期准备事项。 |
| 收到医疗账单 | 找到账单核对、咨询或争议处理的适用入口。 |
| 失业或保险中断 | 找出需要及时核对的保障问题。 |
| 父母需要照护 | 安排当地帮助与家庭分工。 |
| 准备回国 | 区分旅行准备与长期安排。 |
| 收到政府通知 | 确认发出通知的机构与下一步。 |

### 首页建议顺序

先展示搜索框与处境入口，再提供“提前准备”和完整主题目录。下载、阅读工具、方法论与术语放在清晰的辅助导航中。证据和准备顺序筛选可放入可展开的高级选项，保留其功能，降低初次使用的理解成本。

仍应支持按主题阅读、继续上次阅读和打开收藏清单。场景路线补充现有书籍结构；调整导航时保持既有链接有效，避免影响分享、收藏和引用。

### 验收建议

首次访问者从首页经过不超过两次导航操作即可进入各试点场景。手机窄屏上仍能清楚看到标题与主要操作。仅使用键盘也能搜索、选择路线并返回目录，焦点不会丢失。这些目标应通过实际测试确认。

## 2 统一场景页结构

### 先说明适用范围与行动

五个试点场景采用同一基本顺序。首屏应便于快速浏览，同时提供完整解释的入口。每个清单项描述一个可观察的动作，并说明何时需要其他人或机构协助。

| 页面部分 | 应包含的内容 |
| --- | --- |
| 适用对象 | 服务人群、适用地区与重要例外。 |
| 先做三件事 | 最多三项有先后顺序的初始行动及必要分流。 |
| 需要准备 | 所需文件或信息，示例使用空白或虚构内容。 |
| 截止时间 | 触发事件、适用期限与依据；无法确认时明确标注。 |
| 去哪里办 | 用途明确、直接通向机构或服务入口的链接。 |
| 什么时候需要帮助 | 需要合格专业人士或当地协助的条件。 |
| 详细说明和来源 | 判断依据、相关章节、核验日期及尚未解决的问题。 |

### 医疗账单场景的开篇示例

建议标题：**收到医疗账单后从哪里开始**。

目的：帮助读者找到核对账单与联系相关机构的入口。

可考虑的初始动作是：确认收到的是医疗机构账单还是保险理赔说明；整理相关账单与保险文件；确认应联系的医疗机构或保险公司渠道。这些是待编辑的页面结构示例。具体权利、期限和争议处理步骤，需要核对适用条件与来源后才能发布。

随后可按“有保险”“没有保险”“无法确认收费内容”等情况分流。每个分支说明哪些信息会改变下一步。公共网站不收集姓名、账户号码、医疗文件等个人资料。

### 让勾选进度具有明确含义

使用“已找到联系入口”“已准备所需材料”等可观察的完成状态。说明勾选只记录读者进度，不代表获得资格、正式提交申请或解决争议。

### 验收建议

每个试点页使用相同的基本顺序。读者能够判断适用对象，说出下一步，并打开支持该行动的来源。页面总体审查状态不能掩盖局部未核验的期限或例外。

## 3 编辑可靠性与维护

### 区分事实规则 实务建议与示例

事实规则需要直接支持具体主张及其适用范围的来源；实务建议明确标为项目建议；示例使用虚构资料，不暗示所有读者都会得到同样结果。沿用现有编辑制度中“有链接不等于已核实”的区分。

### 复用结构化审查信息

先检查现有台账与字段，能够复用的继续复用，不另建相互冲突的记录系统。

| 字段 | 用途 |
| --- | --- |
| 内容与规则标识符 | 为页面和重要主张提供稳定引用，不重算既有ID。 |
| 地区与人群 | 记录国家、州或地方范围，以及相关资格条件。 |
| 来源与适用时间 | 链接支持来源；必要时记录生效时间或适用年度。 |
| 最后核验与复核期限 | 分别记录实际事实核对时间和下一次计划复核时间。 |
| 审查状态与责任人 | 区分已核验、部分核验、待核验，并明确负责角色。 |
| 已知限制 | 在受影响行动附近解释尚未解决的问题。 |

语言编辑日期与事实核验日期分开。重新排版不更新“最后核验”日期。避免一个页面徽标让读者误以为全部内容已获专业审定。

### 按后果与变化频率安排复核

优先复核期限、资格条件、金额门槛，以及过时信息可能造成较大损失的规则。初步可考虑：高变动事项每月或在权威来源出现变化时复核，较稳定的办理流程每季度复核，一般准备建议每年复核。实际安排应服从现有台账、人员能力与规则变化情况。

逾期内容进入复核队列；影响行动判断时，向读者明确说明哪项陈述需要重新确认。网址仍能打开或服务器返回成功状态，不能证明规则仍然有效。

### 纠错流程

提供与页面对应的“报告问题”入口，预填内容ID。请反馈者指出疑问陈述与支持来源，不要求提交私人文件。优先处理后果较大的错误，同步修订受影响章节与清单，并记录重要更正。需要专业知识或后果较大的事项，应安排适当的第二位审阅者。

## 4 跨境流程与家庭使用

### 明确两地行动如何衔接

项目服务于在美国生活、与中国保持家庭和社会联系的人。可以进一步说明：一地的行动依赖另一地哪些人、材料或机构；谁能在当地处理；下一步开始前必须确认什么。

| 流程要素 | 页面需要回答的问题 |
| --- | --- |
| 地点 | 在美国、中国，还是两地分别办理？ |
| 负责的人 | 本人能否处理，是否需要亲属或合格专业人士？ |
| 前置条件 | 哪份文件、确认或预约必须先完成？ |
| 接收机构 | 谁决定材料或程序是否符合要求？ |
| 时间 | 是已核验的期限、准备时间估计，还是尚待确认？ |
| 完成凭据 | 什么证明该步骤已完成，私人副本应保存在哪里？ |

### 跨境使用文件的流程示例

先确认接收机构的要求，再明确文件种类与签发地。根据已核验来源判断适用的准备、翻译或认证步骤，最后确认接收结果，并在私人系统保留所需记录。不能把一种认证路径写成适用于所有文件和接收机构的统一做法。

### 支持家庭照护分工

父母照护场景可区分紧急当地帮助、日常协调、文件准备与后续跟进。提供空白分工表，包括当地联系人、预约协调人、资料保管人和备用联系人。读者下载或打印后自行填写。

重要清单应便于手机阅读和打印。用自然中文说明行动，必要英文术语首次出现时解释。联系入口要写明用途；需要电话沟通时提供简短可修改的话术示例。

### 验收建议

读者能判断每一步的执行人、地点和前置条件。收到分享链接的家人无需读完前面章节，也能理解当前页面。公开示例没有真实家庭资料，导出与备份说明清楚区分浏览器数据和私人文件。

## 5 搜索 可访问性与工程检查

### 用日常语言测试搜索

先建立20条中文搜索测试用例，覆盖常见处境、口语表达及必要英文缩写。例如“看病太贵”“爸妈来美国”“丢了工作医保怎么办”“国内文件美国能用吗”“收到通知不知道怎么办”。修改排序前，为每条查询指定有帮助的目标页。含义不明确的查询可以引导读者先确认情境。

先测试现有行为，再决定是否需要改动。若当前实现支持，可改善同义词与排序，使可执行场景更容易找到。结果摘要应说明适用范围；没有结果时提供相近主题与替代说法。

### 核对独立访问与检索收录

此前抓取首页时可见JavaScript加载提示和独立章节目录链接。这只是抓取结果，不足以证明章节不可访问或搜索引擎收录不佳。先检查现有静态页面、规范网址和实际渲染行为，再决定是否修复。

- 每章和场景能通过稳定网址直接打开，刷新后仍正常。
- 禁用JavaScript时可读取正文；页面标题、描述与站点地图能区分具体内容。
- 保留既有锚点；改变网址时提供兼容映射或重定向。

### 按改动范围检查

先阅读现有构建与测试脚本，补足缺失的内部链接、重复ID、必要审查字段、自动生成数量与Markdown渲染检查。定期检查外链并允许重试，区分访问受限与确认失效；临时外部故障不应触发自动删除内容。

读者流程发生变化时，核对搜索、收藏、勾选保存、打印、离线、备份与恢复。检查键盘导航、可见焦点、对比度、标题顺序和中文换行。使用手机尺寸与放大文字进行测试；实体设备任务仍按仓库现有要求另行完成，不能用模拟视窗替代。

### 验收建议

试点没有已知失效内部链接或阻断操作的键盘问题。更新保留已有阅读数据，或提供经过验证的迁移与恢复方法。重要回归检查有可复现结果。外部来源是否支持结论属于编辑核验，不与自动化技术检查混为一谈。

仓库完整检查入口为 `python scripts/validate.py`；`--quick` 不作为发布验收。参见[开发与发布](development.md)。

## 6 实施优先级与建议进度

下表是本方案的实施优先级，与正文的准备优先级标签不同。工作量仅供初步规划，检查当前实现后再调整；已有功能不重复开发。

| 编号 | 交付内容 | 建议顺序 | 相对工作量 |
| --- | --- | --- | --- |
| A | 选择五个试点场景，记录当前读者路径 | 首轮 | 小 |
| B | 确定场景模板与复用的审查字段 | 首轮 | 中 |
| C | 审查试点中的重要事实陈述 | 首轮 | 大 |
| D | 调整试点对应的首页入口 | 首轮 | 中 |
| E | 测试20条搜索查询，改进较弱结果 | 随后 | 中 |
| F | 核对独立网址，补足必要内容检查 | 随后 | 中 |
| G | 补充跨境前置条件与家庭空白分工表 | 随后 | 中 |
| H | 真实读者试读，解决发布阻断问题 | 首轮 | 中 |
| I | 把通过验证的模板逐批推广 | 后续 | 大 |

### 第1至15天

维护者选定五个场景，确定内容与工程负责人；一人可承担多个角色。盘点已有模板、字段、测试和公开网址。记录代表性读者完成任务的基线，建立搜索测试集。交付试点范围说明和经检查确认的实现缺口。

### 第16至30天

内容负责人按统一结构修订五个场景页。审阅者核对重要事实，记录未解决问题。工程负责人实现已确定的导航与审查信息展示。阶段交付应是可审阅的页面和可重复运行的构建。

### 第31至60天

邀请五位目标读者试用，修复重复出现的理解困难，运行发布检查。满足验收条件后再发布。收集具体失败任务与适用条件不清的问题，并据此调整复核队列与纠错流程。

### 第61至90天

把有效模板逐批用于其他场景，优先选择常用、后果较大的事项。完善跨境流程与搜索覆盖。在扩展主题或交互功能之前，评估维护负担是否可持续。

能力有限时可把试点缩为三个场景，保留审查质量。先后顺序比日期重要：先确定模板和字段再批量迁移；先事实审查和真实试读再发布。进入实际实施时，在对应Issue记录范围、验收条件和负责角色。

## 7 验证与发布条件

### 使用真实的读者任务

邀请五位接近目标人群的读者，覆盖不同程度的美国生活经验。使用虚构场景，不要求参与者提供真实医疗、移民或财务信息。每人完成三项任务，观察时不进行操作指导。

每项任务要求读者找到适用页面、用自己的话说明下一步、找到官方来源。记录耗时、错误路径、误解，以及是否理解适用限制。使用相同或等价任务与基线比较。

| 指标 | 建议试点目标 |
| --- | --- |
| 找到适用页面 | 每项任务至少4人能在60秒内找到。 |
| 理解下一步 | 至少4人无需指导即可指出恰当行动。 |
| 理解适用范围 | 没有尚未解决、可能造成重要后果的适用性误解。 |
| 找到依据 | 至少4人能找到相关来源与核验日期。 |
| 搜索相关性 | 20条查询中至少18条的前三项结果包含有帮助的目标。 |
| 审查覆盖 | 每项重要事实都有适用范围、来源与明确审查状态。 |

这些是建议目标，不是现有成绩，也不能作为统计结论。五人试读用于发现使用障碍，不能证明所有人都能顺利完成任务。即使达到数值目标，严重误解仍应单独处理。

### 发布判断

试点达到读者目标、重要事实缺口已解决或范围已合理限定，并且改动流程通过回归检查后，由维护者确认发布。未经核验的重要指令不能标为“已核验”。未解决问题会改变读者行动时，应先修正、缩小或暂缓该指令。

分支、PR与完整检查按[维护者入口](../../AGENTS.md)执行。本方案本身不授权自动合并、部署或扩大实施范围。

### 恢复与持续复核

保留可恢复的上一版和明确回退步骤。新版本若破坏阅读数据或关键路径，优先恢复服务，再定位问题。事实更正应同步受影响页面，并说明更正范围。

每月检查逾期重要事实、未处理反馈、失效官方办理入口和反复出现的搜索失败。能用自愿反馈和汇总观察解决的问题，不额外收集个人信息。没有明确用途及相应数据处理设计时，不保存可能包含隐私的原始查询。

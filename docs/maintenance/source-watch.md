# 少量官方来源变化提醒

这是人工事实复核的辅助入口，对应 [Issue #6](https://github.com/gjimzhou/US-China-Life-Playbook/issues/6)。不自动改正文、`last_verified`、到期日或证据记录，不替代已有的到期队列与外链检查。

## 试行范围与节奏

配置在 `maintenance/source-watch.json`，责任分工按范围交给对应内容维护者，不登记私人联系人。

| 官方页面 | 人工复核范围 | 官方订阅优先级 |
|---|---|---|
| CDC COVID临床指导总页 | 第02章第3节：季节、版本日期及监管说明 | 页面提供CDC邮件订阅；维护者可自行选择，不由程序填写邮箱 |

工作流 `Official source change watch` 每日14:17 UTC运行，也支持手动运行和相关源码更新触发。GitHub调度可能延迟；检查失败和长期停用需维护者处理。PR只跑离线受控测试，不访问来源或写Issue。

## 怎样产生提醒

每次各请求一次，25秒超时，不在429／403后密集重试。只接受配置允许的官方HTTPS域名；跨出允许域名的重定向、非HTML、超大响应、缺失／多个正文区及明显过短内容都作为失败。源码只取一个`main`区，忽略导航、脚本、样式、反馈表单等，并归一化空白；正文中的链接目标也计入指纹，以捕获公告链接更换。

- 指纹不同：保留人工复核任务，最多列最近10种变化指纹。内容后来恢复原样也不自动抹去待办。
- 连续两次检查失败：产生访问故障提示。计数在两次封顶，相同失败不反复修改Issue；成功后清除故障提示，但不清除未复核变化。
- 无变更／相同未决状态：不创建评论、不重复修改Issue。所有信号合并为一个带专用标记的Issue，与到期队列Issue分开。
- 手动关闭但未处理基线：下次重新打开。只有人工PR接受新的基线，或故障恢复且没有内容变化待办，才自动关闭。

页面布局、相关链接、日期或措辞调整也可能触发提醒；这不是政策变化分类器。正文外的变动、同一URL下PDF内容的替换和其他未配置页面不在检测范围。不能把“无信号”写成政策未变化或事实已核验。

## 状态与丢失处理

GitHub Actions 的 `source-watch-state` 附件保存连续失败和未复核指纹，保留90天；每次从同一工作流最近的已完成主分支运行恢复，不读取PR附件。同一分支的检查串行运行，避免覆盖状态。首次运行使用配置中的已接受指纹；之后找不到可用附件或附件损坏会明确失败，不悄悄重建基线。工作流故障纳入现有失败追踪Issue。

若状态丢失，先调查附件保留期、删除、运行中断与上传失败，恢复已知有效状态；不要为了消除报错覆盖基线或清空待办。重新运行时优先恢复该次运行前一尝试的附件，保留未决变化；新的网络检查计为一次新的观测。

已有更新的主分支检查完成时，拒绝重跑较旧运行，避免旧状态覆盖新信号；应从当前主分支手动启动新检查。

## 人工复核与接受基线

1. 打开信号中的官方原文，对照具体章节、来源日期和适用条件；必要时读取链接的公告、表格或PDF。
2. 按事实复核流程记录实际覆盖及缺口，必要时修改正文和关联清单。纯布局／链接排序变化记录为误报，不刷新事实核验日期。
3. 本地运行 `python scripts/source_watch.py` 进行只读采集。结果在 `_maintenance/source-watch/`，不会写GitHub或维护台账；输出的 `sha256` 是候选指纹，不是已核验结论。
4. 审阅全部未决信号后，通过PR更新对应 `accepted_sha256`。变更提取方法时也需重采并人工检查三项基线，不得自动接受所有新指纹。
5. 合并后检查工作流、状态附件与Issue是否按预期恢复安静。

配置日期仅表示建立比较基线，不是事实核验日期。程序和测试均不能宣称取得医学／法律专业审定。
